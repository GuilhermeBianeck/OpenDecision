# OpenDecision progress

Updated 18 September 2026 (report matrix on the expanded corpus).

## Completed

- Bootstrapped the installable `opendecision` package and MIT-licensed repository.
- Added Pydantic schemas, normalization, confidence margin, calibration, abstention,
  independent multi-label decisions, ranking, and bounded batch APIs.
- Added pinned DeBERTa, ModernBERT, Skywork Reward, BGE reranker, deterministic
  demo, and experimental content-addressed ONNX backends.
- Added explicit model download and offline-only inference (`local_files_only`,
  safetensors, remote code disabled), model-license records, and device diagnostics.
- Added FastAPI server with resident startup load, loopback default, request/body
  bounds, concurrency gate, health/models endpoints, and typed decision routes.
- Added a dependency-free TypeScript HTTP client with timeout and structured errors.
- Added synthetic benchmark generation, grouped data splits, objective/control/
  ranking/subjective/ambiguous/trolley families, ECE/Brier/NLL/AUROC, selective
  metrics, robustness probes, and JSON/Markdown reports.
- Added an optional, explicitly invoked generative LLM baseline adapter. No secrets
  or external credentials are committed.
- Added CI, Docker examples, Python examples, docs, and focused tests.
- Scored booleans and multi-label questions as statements on NLI backends
  (entailment against contradiction, with `unsupported` as the neutral share and
  `unsupported_threshold` to abstain on it).
- Added the ordered rubric primitive (`score`), option descriptions (`ChoiceOption`),
  structured state (records and lists), and `ask` for mixed typed questions about
  one state under caller ids; every result carries a `type` discriminator.
- Recorded fitted candidate counts in calibration profiles; made `device="auto"`
  prefer MPS on a published measurement; made the default sequence limit the model
  context capped at 2,048 tokens.
- Added the `decoder` backend (pinned Qwen3 0.6B): one KV-cache prefix per distinct
  state, options scored by their letter's next-token log-probability, at most 26
  options, optional rotation averaging.
- Taught the benchmark runner boolean and score kinds with verification, robustness
  and ordinal families, per-family and per-variant metrics, and compact reports;
  expanded the corpus to 538 seeds in 101 groups (6,578 rows) with templated
  verification statements, negation pairs, embedded and authority-styled
  injections, twelve-option routing, six rubrics, and same-domain distractors.

## Verified evidence

The dependency-free suite covers schemas, backend contracts, registry, statement
scoring, rubric scoring, structured state and options, typed questions,
calibration, benchmark metrics, CLI, and HTTP behaviour: **143 passed, 5 optional
weight tests skipped** in the default run. TypeScript build and five client
contract tests pass. Opt-in real-weight tests pass for tiny, base, smart,
multilingual and decoder on the reference machine.

### Report matrix on the expanded corpus

All five backends were run on the full 1,726-row test split of the 6,578-row
corpus (dataset SHA-256 `43c4923ea723…`) on the reference 16 GB Apple Silicon
machine, MPS, float32, one request per call. The complete matrix, including
per-family and per-variant accuracy, is generated by `scripts/compare_reports.py`
into [benchmarks/reports/README.md](benchmarks/reports/README.md); the JSON
reports hold every prediction. Headline numbers, pooled over the objective,
agent-control, verification and robustness families (n = 1,158):

| Backend | Accuracy | ECE | Accuracy at margin ≥ 0.5 (coverage) | Warm p50 |
| --- | ---: | ---: | ---: | ---: |
| `tiny` | 0.576 | 0.127 | 0.766 (0.462) | 24.5 ms |
| `base` | 0.675 | 0.149 | 0.830 (0.472) | 28.7 ms |
| `smart` | 0.616 | 0.086 | 0.730 (0.441) | 107.0 ms |
| `multilingual` | 0.512 | 0.201 | 0.531 (0.451) | 58.8 ms |
| `decoder` | 0.604 | 0.275 | 0.608 (0.786) | 158.1 ms |

What the families show, with the number of test rows in each slice:

- **Verification is where the NLI statement path is strong** (n = 352): `base`
  0.966 and `tiny` 0.932 against 0.810 for the reward model's yes/no choice and
  0.682 for the decoder, which accepts false statements as true (0.493 on
  `target = no`). The decoder's `unsupported` signal is nonetheless the most
  separated (mean 0.802 on unaddressed-or-false statements versus 0.154 on true
  ones; `base` 0.384 versus 0.050).
- **Wide twelve-option routing favours the decoder** (n = 156 rows, 12 seeds):
  0.699 overall and 0.917 on unperturbed states, against 0.429 / 0.667 for `base`
  and 0.250 / 0.333 for `tiny`. The cross-encoders also pay one forward pass per
  option here; the decoder pays one.
- **Negation is near chance for every cross-encoder** (n = 234 rows, 18 seeds):
  on unperturbed rule-plus-fact states `tiny` and `base` score 0.500 on a two-way
  choice, `smart` 0.667, `decoder` 0.611. The NLI models choose the same option
  whether the fact is affirmed or negated.
- **Embedded instructions steer every backend** (n = 52 rows, 4 seeds): `base`
  and `multilingual` follow the injected instruction on every row (0.000), `tiny`
  0.058, `smart` 0.077, `decoder` 0.269. The `authority_injection` variant, which
  appends a bracketed system line naming a wrong option, moves pooled accuracy
  from 0.777 to 0.426 for `base` and from 0.638 to 0.085 for the decoder; the
  models pick exactly the named wrong option on 69–98 % of those rows. The
  hypothesis template for NLI is lexically entailed by text that names an option,
  so this is a property of the approach, not of one checkpoint.
- **Rubrics** (n = 216): exact level 0.352–0.606, within one level 0.755–0.898;
  `smart` is best on both, `base` reaches 0.417 / 0.852. Ordinal errors are in
  level steps and the six rubrics are short.
- **Ranking** (n = 52): NDCG 0.983 (`multilingual`), 0.982 (`decoder`), 0.874
  (`base`).
- **Ambiguity** (n = 96, abstain threshold 0.55): `base` abstains on 0.573 of
  cases that should abstain; the decoder on 0.073 and `smart` on 0.083, matching
  their higher ECE — the decoder is overconfident and needs a calibration profile
  or a higher threshold before its coverage numbers mean anything.
- **Same-domain distractors** cost every backend 10–15 points (`distractor_middle`
  0.628 for `base` versus 0.777 unperturbed).

The 24-case CPU validation reports from the first alpha remain in
`benchmarks/reports/` under their own dataset hash; they measured plumbing on
a corpus one twentieth this size and are superseded by the matrix above.

The corpus is correlated project-authored data: 538 seeds in 101 semantic groups
expanded by deterministic variants. Slice sizes above count rows; the number of
independent scenarios behind each is far smaller, and no human adjudication has
taken place. These reports are baseline measurements, not a superiority claim.

### Calibration

Temperature is fitted per candidate count on the calibration split (741 labeled
choice rows: 416 binary, 208 four-way, 117 twelve-way) and measured on the
untouched validation split. Sharpness depends strongly on width, so one pooled
temperature fits none of the groups:

| Backend | Pooled T | T for k=2 | T for k=4 | T for k=12 | Validation ECE | Validation NLL |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `tiny` | 9.10 | 100.00 | 0.81 | 1.84 | 0.251 → 0.129 | 1.378 → 1.115 |
| `base` | 2.29 | 9.55 | 0.39 | 0.30 | 0.221 → 0.136 | 1.060 → 0.896 |

Accuracy is unchanged on both sides, as temperature scaling never reorders
candidates. Binary rows need heavy smoothing while wide rows need sharpening —
the models are underconfident once their mass spreads across many options.
`tiny` reaching the T=100 boundary for binary rows is a fit at the edge of the
search domain and should be read as "this model's binary scores carry little
usable signal", not as a well-determined temperature. Profiles for `tiny` and
`base` are committed under `calibration/`.

## Remaining work

- Fit profiles for `smart`, `multilingual` and `decoder`, and per task family;
  the decoder in particular is overconfident (test ECE 0.275) and abstained on
  only 7.3 % of ambiguous cases without one.
- Extend calibration to the statement and rubric paths, which are scored through
  different code and are currently excluded from fitting.
- Address negation and instruction steering, which every current backend fails:
  candidate serialization that does not lexically restate the option, a small
  fine-tune on the training split with held-out groups, or an instruction-free
  prompt for the decoder are the obvious experiments.
- Measure `permutations` for the decoder and the `short` template for the
  cross-encoders on the validation split before changing defaults.
- Collect independently adjudicated, consented deployment data and calibrate per
  task family. Preserve final groups while training any candidate scorer.
- Implement dynamic request batching for the server, CoreML measurement, and an
  optional Pydantic AI adapter only when benchmark evidence justifies them.
- Publish a release only after package metadata, changelog, model notices, and
  release checks are reviewed.

## Deviations from the master specification

The alpha does not claim low-double-digit latency for every backend, parity
with hosted decision services, independent human-validated examples, automatic safe decisions, full score/rubric parity, or that MPS is faster
than CPU. Those are explicit research targets. External APIs are optional and
never required for local inference. Timestamps in this progress note describe
actual work and measured runs; repository history is kept truthful.
